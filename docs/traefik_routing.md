# Traefik Routing & Landing Pages (state model)

How a request to `<pod_id>.pods.<tenant>.<base>` is routed, and what the user sees when the pod
isn't serving its real app. Companion to `CLAUDE.md` → "Traefik Integration" (HTTP provider, router
naming, access logs) and `docs/cert_fallback.md` (TLS cert issuance).

## Ingress chain

```
browser ──HTTPS──> HAProxy ──(L4 SNI passthrough)──> nginx ──(*.pods.* + fallback)──> Traefik ──> pod / pods-api
```

- **HAProxy / nginx** do L4/SNI routing only. **Traefik terminates TLS** (per-domain Let's Encrypt;
  see `cert_fallback.md`). nginx also passes a fallback to Traefik because postgres pods need TCP.
- Traefik config is an **HTTP provider**: `GET /traefik-config` (api_misc.py) serves the live
  Jinja-rendered `templates/traefik-template.j2`. The render is produced by `set_traefik_proxy()`
  → `update_traefik_configmap()` each health-loop tick (see below).

## Per-pod routing decision (in `set_traefik_proxy`, health_central.py)

`set_traefik_proxy` iterates **every pod in the DB** (running or not) and, for each `http`
networking entry, emits one router. The router points at either the **real pod backend** or the
**splash page**, decided by `networking_live`:

```
pod_networking_live = _is_pod_networking_live(pod, input_pod):
    status == AVAILABLE  AND  (no readiness gate  OR  status_container['ready'] is True)

splash_mode = not pod_networking_live      # per pod
```

| Situation | `networking_live` | Router target |
|---|---|---|
| Running & ready (or no readiness gate) | True | **real pod** `k8_name:port` |
| AVAILABLE but readiness probe not passing | False | **splash** → `pods-api:8000` (rewrite → `/pod-splash`) |
| STOPPED / ERROR / CREATING / REQUESTED / COMPLETE / DELETING | False | **splash** → `/pod-splash` |
| **No pod at all** (deleted / never existed / mistyped) | — (no router) | **catch-all** → `/pod-not-found` |

Splash routing is applied by the `tapis-splash-<name>` middleware
(`replacePathRegex: ".*" -> /pod-splash`) attached to the router when `splash_mode` is true. The
catch-all router (`catch-all-error-handler`) uses `not-found-rewrite` (`".*" -> /pod-not-found`).

> Note: because routers are emitted for **all** pods, a STOPPED pod still has a splash router → its
> domain hits `/pod-splash` (which then shows a "stopped" message — see below). Only genuinely
> router-less hosts fall to the catch-all `/pod-not-found`.

## 🚫 Cert state must NEVER gate routing

`cert_ready` / `cert_state` (written by `_evaluate_http_cert`) are **visibility-only** — action
logs, admin timings, and the UI holding page read them, but they do **not** influence `splash_mode`
or any router. This is a hard rule, learned the hard way:

- An earlier "hold splash until cert ready" **deadlocked issuance** (the splash rewrite catches
  Traefik's ACME `/.well-known/acme-challenge/...` path) and took healthy pods offline.
- The readiness signal comes from an **in-cluster** TLS probe that often can't reach the public URL
  through HAProxy/nginx, so it false-negatives. `_probe_cert_status` therefore returns
  **ready / invalid / unreachable** and never conflates "can't reach" with "cert bad."

Certs are issued by Traefik on the first real hit; the residual window is covered by pre-warming
(the health-loop probe) + the tapis-ui **PodLaunch** holding page. See `cert_fallback.md`.

## Landing pages — one status-aware renderer (`api_misc.py`)

Both `/pod-splash` (routed pods not serving their app) and `/pod-not-found` (router-less hosts)
call **`_render_pod_status(request)`**. It reads the original host (`X-Forwarded-Host` / `Host`),
parses `<pod_id>` + `<tenant>` out of `<pod_id>[-<net>].pods.<tenant>.<base>`, looks up **only**
`pod.status`, and renders the matching page:

| `pod.status` | kind | HTTP | auto-refresh |
|---|---|---|---|
| REQUESTED / SPAWNER SETUP / CREATING / RESTART / unknown | starting | 503 | yes |
| AVAILABLE (readiness/cert gate) | securing | 503 | yes |
| DELETING | deleting | 503 | yes |
| STOPPED / OFF | **stopped** | 503 | no |
| ERROR | error | 503 | no |
| COMPLETE | finished | 503 | no |
| pod not found / host unparseable | notfound | 404 | no |

**Security:** the page reveals only the coarse status — never name/image/config/env/secrets/logs —
and does not echo the `pod_id` into the body (it's already in the URL). DB errors are swallowed →
"not found". Both endpoints are allow-listed as `NOT-API` in `auth.py` (like `/healthcheck`).

**TLS caveat:** a host that never had a cert fails the browser TLS handshake (default cert) *before*
any of these pages can render. So the landing pages help hosts that already have a cert (stopped
pods, wrong paths). Covering every invalid subdomain cleanly needs a `*.pods.<tenant>` wildcard
default cert (DNS-01) — see `cert_fallback.md`.

## Applying changes (dev)

- Config is regenerated by **`pods-health-central`** (`set_traefik_proxy` runs each tick);
  `pods-health` runs the pod-status loop (`health.py`).
- All services **hostPath-mount** the local `service/` dir, but a running process keeps old code in
  memory. After editing `health_central.py` (config gen) or `api_misc.py` (landing pages):
  `kubectl rollout restart deploy/pods-health-central` and/or `deploy/pods-api`.

## ⚠️ Editing `traefik-template.j2` — MUST render-test with multiple pods

Jinja whitespace control in this template is fragile. A conditional around a router field
(`{% if %}/{% else %}/{% endif -%}`) can emit stray leading spaces that glue onto the **next**
router's key (the `-%}` eats the separating newline) → a 6-space-indented router key → the whole
`http.routers` block is malformed → **all routes 404**. A single-pod render will NOT catch this.

**Rule:** before shipping any template change, render it with **≥3 http pods** (including one with
`tapis_auth` exclusions and one in `splash_mode`) and parse the output with `yaml.safe_load`,
asserting no router key is indented at 6 spaces. (See the render checks used during the cert work.)
